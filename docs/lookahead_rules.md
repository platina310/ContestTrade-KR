# Look-ahead 방지 규칙

## 기준 시각

- **시그널 확정**: 거래일 D 08:30 (KST). 이 시각까지 관측 가능한 정보만 D 시그널에 쓴다.
- **체결 가정**: D 시가(09:00 동시호가 체결가). 시가는 체결가로만 쓰고 피처로는 쓰지 않는다.
- D 08:30 이후에 생긴 정보는 모두 D+1 시그널로 넘긴다.

## 소스별 컷오프

| 소스 | D 시그널에 사용 가능한 조건 | 그 외 | 비고 |
| :-- | :-- | :-- | :-- |
| DART 공시 | 접수 시각이 있고 **시각 ≤ D 08:30** → D. 시각이 없으면 **rcept_dt < D** (달력 기준) | 접수 시각이 08:30 이후 → **D+1** | OpenDART `list.json`은 접수 **일자만** 제공. 시각이 없으면 접수일 D 공시는 **D+1**에 사용 (보수적). KIND 공시 시각으로 `rcept_time`을 보완하면 위 규칙 적용 |
| Factiva 서울경제 (ET 있음) | **pub_dt_kst < D 08:30** | 그 이후 → D+1 | Factiva PD+ET는 실제 KST보다 **+9h** 늦게 찍힘 → `pub_dt_kst = PD+ET−9h` (파서가 생성). 2026-09-24 사이트 수정시각과 2건 분 단위 대조로 확정(06-30 18:46, 05-31 09:18). ET는 입력이 아닌 **수정시각** 기준이라 보수적 |
| Factiva 한경·매경 (날짜만) | **pub_date < D** (달력 기준) | pub_date ≥ D → D+1 이후 | PD도 +9h 쪽으로 늦게 찍히므로(실제 날짜 ≤ PD) 이 규칙은 누수 없이 보수적 |
| 수급·시세 (pykrx) | **D-1 종가·D-1 투자자별 순매수까지** (D-1 = 직전 거래일) | D 당일 시세·수급은 사용 금지 | 시가총액·지수도 D-1 기준. D 시가는 체결가 전용 |
| 텔레그램 (증권사 리서치 4채널) | **메시지 시각 < D 08:30** | 08:30 이후 메시지 → D+1 | 포워딩 메시지는 채널 게시 시각 기준(원문 시각 아님). 편집된 메시지는 원 게시 시각 기준. 서버 타임스탬프 UTC → KST 변환은 어댑터 한 곳에서만 |
| 콘테스트 점수 (ZI 채점·리서치 성과) | **D-2일 산출물의 점수까지** | D-1 산출물 점수 → D+1 배분부터 | 채점 수익률은 시가→시가 `open(d+1)/open(d)−1`. d 산출물 점수는 d+1 09:00에 확정되므로 d+1 08:30 결정에는 쓸 수 없음 |

**달력 기준 vs 거래일 기준**: 날짜만 있는 텍스트 소스(공시·뉴스)는 `< D`(달력)로 거른다. `≤ 직전 거래일`로 거르면 주말·휴일 기사/공시가 월요일 시그널에서 빠져 하루 늦게 반영된다. 시세·수급만 직전 거래일 기준이다.

## 구현 규칙

1. 모든 어댑터는 `trigger_time`(= D 08:30)을 입력으로 받고, 위 컷오프를 SQL `WHERE` 절에 직접 건다. 어댑터 밖에서 필터링하지 않는다.
2. 날짜 컬럼은 문자열 `YYYY-MM-DD`, 시각은 `HH:MM`(KST), 날짜+시각은 `YYYY-MM-DD HH:MM`(KST)로 통일한다. 시각이 없는 소스는 `NULL`로 두고 날짜 규칙을 적용한다.
3. D-1(직전 거래일)은 `market.sqlite`의 `prices` 테이블에 존재하는 날짜로 판정한다.
4. 백필·재수집 후에는 `collected_at`/`ingested_at`이 아니라 **원 게시/접수 시각**을 기준으로 필터한다.
5. 에이전트 메모리·reflection 저장소가 있으면 백테스트 실행 전에 초기화한다. LLM 출력 캐시는 (날짜, 에이전트, 입력) 키가 같을 때만 재사용한다.

## 검증 쿼리 예시

```sql
-- DART: 시각이 없는 공시가 접수일 당일 이후 시그널에 들어갔는지 (0건이어야 함)
SELECT COUNT(*) FROM disclosures
WHERE rcept_time IS NULL AND rcept_dt >= :D;

-- Factiva 서울경제: D 08:30 이후 기사 유입 여부 (0건이어야 함)
SELECT COUNT(*) FROM factiva_news
WHERE pub_dt_kst IS NOT NULL AND pub_dt_kst >= :D || ' 08:30';

-- Factiva 한경·매경: D 당일 이후 기사 유입 여부 (0건이어야 함)
SELECT COUNT(*) FROM factiva_news
WHERE pub_dt_kst IS NULL AND pub_date >= :D;

-- 시세: D 당일 행 유입 여부 (0건이어야 함)
SELECT COUNT(*) FROM prices
WHERE date >= :D;

-- 텔레그램: D 08:30 이후 메시지 유입 여부 (0건이어야 함)
SELECT COUNT(*) FROM telegram_messages
WHERE msg_datetime >= :D || ' 08:30';
```

위 쿼리는 어댑터가 **반환한 결과**에 대해 돌린다(원본 테이블 전체가 아님). 어댑터 단독 테스트에서 모두 0건임을 확인한 뒤 `python -m cli.main run`을 돌린다.
